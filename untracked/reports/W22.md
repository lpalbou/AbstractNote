## Design decisions
- Staleness is structural (ADR 0004): empty; the creation placeholder = the creating revision carries the
  revision builder's own warning sentence for one of the entry's names and no summary was written since;
  changed = an `entity_notes` row or a non-retracted claim (entry or merged members) recorded by a revision with
  a higher `seq` than the entry's latest summary revision. `summary_revision_count` = that seq. No marks table.
- Summaries go through the revision log (`action: entity.summary`, run_id = consolidation id), so rebuilds
  replay them and `summary_history` keeps versions.
- The run is identified by the open `consolidation_runs` row (the tools take no run id, as briefed); the gateway
  view adds `run_id` from the automation's latest occurrence when it is running/waiting, and reports an open row
  whose occurrence already ended as `last.status = interrupted`.
- Loops: `labels_continue`/`sum_continue` are cleared at the start of every round and set again only at its end;
  a node raising inside a round (branch complete) therefore ends the loop with `*_inflight` still set, and the
  check after the loop fails the run with a sentence. An llm_call failure is an effect failure: the run ends at
  once (row left open -> interrupted). A skipped entry is not offered again in the same run (`offered_json`).
- Schedule: `off` keeps the automation paused (flag `consolidate_paused_by_setting`), turning it on resumes only
  a pause the setting made; a user pause survives a repair. First occurrence one interval after creation.
- Model: the answering model (as reflect). Thinking: start pin `thinking`, default off, wired to both llm nodes.
